# OVION — أوفيون

تطبيق أندرويد (Kotlin + Jetpack Compose) فوق Supabase. واجهة عربية RTL، وضع فاتح/داكن تلقائي.

## اللي شغال في هذا الإصدار
- تسجيل / دخول (نفس الموجود قبل كده) + تجديد الجلسة تلقائياً.
- منشورات نصية + صورة، تعديل وحذف لصاحب المنشور فقط.
- إعجاب (بعدد حقيقي)، تعليقات وردود، مشاركة (Intent + عداد).
- قوائم: الأحدث / الأكثر تفاعلاً. تحديث تلقائي كل 20 ثانية في الرئيسية.
- ملفات شخصية: صورة، غلاف، نبذة، اسم مستخدم، متابعة/إلغاء، أعداد المتابعين، منشورات المستخدم.
- رسائل خاصة (تحديث كل 4 ثواني داخل المحادثة) + عداد غير مقروء.
- إشعارات (إعجاب/تعليق/متابعة) + عداد غير مقروء.
- بحث عن أشخاص ومنشورات + استكشاف + حسابات مقترحة.

## مش موجود لسه (بصراحة)
- رفع فيديو، إعدادات الخصوصية (العمود موجود في قاعدة البيانات بس الواجهة والتطبيق مش متنفذين)، إشعارات Push خارج التطبيق.
- التحديث "الفوري" حالياً Polling دوري مش WebSocket. جداول messages/notifications مضافة لـ Realtime في SQL لو حبينا نحوّل بعدين.

## خطوات Supabase (مرة واحدة)
1. افتح Supabase > SQL Editor وشغّل `supabase_schema.sql` (لو متشغّل قبل كده تخطاه).
2. شغّل `supabase/migrations/002_social_features.sql`.
3. Authentication > Providers > Email: لو عايز التسجيل يدخل على طول من غير تأكيد بالبريد، اقفل "Confirm email".
4. Storage: الـ bucket `media` بيتعمل من الـ SQL. اتأكد إنه ظاهر وPublic.
5. (اختياري) شغّل `supabase/tests/rls_test.sql` للتأكد من الصلاحيات — كله بيتلغي في الآخر.

مفيش `service_role` في التطبيق. المفتاح الموجود publishable (مصمم يكون في التطبيق) والأمان من RLS.

## البناء
- GitHub Actions: ارفع على فرع `main` وهيبني `app-debug.apk` (Artifacts). أو Actions > Run workflow.
- محلياً: Android Studio (JDK 17) > Open > Run. أو `gradle assembleDebug`.
- اختبارات الوحدة: `gradle testDebugUnitTest`.

## هيكل الكود
`Api.kt` اتصال Supabase • `Models.kt` النماذج والـ parsing • `Ui.kt` الثيم والمكونات • `Screens1.kt`/`Screens2.kt` الشاشات • `MainActivity.kt` الجذر والتنقل.
ملفات الويب القديمة (CONNECTO: index.html وغيره) متساباش زي ما هي ومش بتأثر على التطبيق.
